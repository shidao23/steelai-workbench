# T63 人工、单智能体与多智能体流程评估

T63 不用界面演示代替效果证明，而是在同一套材料科研任务上比较三种流程：纯人工、单智能体、受治理的多智能体。当前已经冻结任务、输入、检查项、关键错误、重复次数、指标和判定规则；真实人工测量尚未完成，因此状态是 `Review / needs_human`，不能提前宣称智能体更高效。

## 固定任务与流程

任务集包含四类典型工作：公开钢铁数据检查、T62 统计结果解释、Physics 缺失输入判断、受证据约束的报告整理。每项任务分别采用 `human_only`、`single_agent`、`multi_agent` 完成两次，共需 24 条真实记录。

三种流程必须使用同一输入版本和目标。失败、阻断、取消和无优势结果都必须保留，不允许只展示成功案例。

## 冻结指标

- 完成率：完成全部必需检查且没有关键错误的任务比例。
- 关键错误：只统计任务契约中预先登记的严重错误。
- 人工修订次数：首版输出后发生的实质性人工纠正次数。
- 耗时：带时区开始与结束时间对应的墙钟时间。
- Token 与云端费用：使用服务商记录或固定价格计算；未调用云模型时才允许为零。
- 追溯完整率：该流程要求的轨迹字段实际存在比例。

智能体流程只有在完成率不低于人工、关键错误不多于人工、追溯完整率不低于人工，并且中位耗时至少减少 10% 或平均人工修订至少减少 0.5 次时，才满足冻结优势规则。费用必须同时报告，但低成本本身不代表质量更高。

## 准备评测

双击项目根目录的 `Run_T63_Benchmark_Prep.cmd`，或执行：

```powershell
.\.venv\Scripts\python.exe -B -m steelai.agent_workflow_benchmark
```

系统会在 `outputs/agent_workflow_evaluations/<publication_id>/` 创建仅追加治理包。初次生成包含 12 条结构校准记录和一张 24 行的 `measurement_template.csv`。校准记录只验证结构、评分与报告链路，明确排除在优势结论之外。

## 完成真实测量

1. 复制准备包中的 `measurement_template.csv` 到仓库外的个人测量目录，避免把个人身份、提示词或回答原文加入公开仓库。
2. 按固定顺序完成四项任务；每种流程、每项任务各两次。
3. 填写时间、状态、通过项、关键错误、人工修订、Token、费用、实际轨迹字段和操作者代号。列表字段使用 `|` 分隔。
4. 运行评估：

```powershell
.\.venv\Scripts\python.exe -B -m steelai.agent_workflow_benchmark --records "测量表完整路径"
```

只有 24 条测量完整、没有重复且通过治理校验，系统才给出冻结规则下的比较判断。输出包括原始记录 JSONL、比较表、结果 JSON、中文报告、Manifest 和 COMPLETE 完整性标记。

## 科研边界

- 当前准备包为 `working_candidate`，需要人工完成真实计时和复核。
- 评估结论只适用于这四项固定任务、当次模型版本和运行环境，不能外推为所有科研任务都更优。
- 结果包不保存问题原文、模型回答、私有实验值、本机绝对路径或密钥。
- 单智能体或多智能体没有达到优势门槛时，系统会如实记录 `no_agent_workflow_advantage_detected`。
- T63 不授予智能体审批、正式写入、修改来源或执行任意命令的权限。
