# SteelAI Workbench 用户操作指南

## 使用目的

SteelAI Workbench 用于组织个人材料科研中的数据接入、确定性计算、统计、图像与模型任务、证据解释和成果整理。系统负责记录身份、人工决定、质量状态、来源和完整性；研究者仍然负责确认样品对应、单位、参数、结论和公开范围。

## 日常操作顺序

1. 在“科研总览”确认当前样品、科研会话和统一运行状态。
2. 在“数据与物理”登记输入。字段映射和单位存在不确定性时，保持 `needs_human`，不要强行执行。
3. 人工确认来源、字段、单位和试样对应关系后，才允许标准化、逐值 QC 与仅追加提交。
4. Physics Engine 先检查输入完整性，再选择公式版本和适用范围。结果始终作为经验估算展示。
5. 可追溯统计只读取已验证输入，登记统计单位、纳入决定和方法版本，生成描述统计与组级 QC。
6. EBSD、SEM 或模型实验先登记原始文件身份和参数，再在独立环境执行；输出必须经过人工复核才可形成结果索引。
7. 研究助手只读取已验证的结构化证据。事实、判断和假设必须分开，回答不能直接写入科研数据或替代审批。
8. 在“研究助手 → 运行与成果”集中处理待人工确认、被阻止和完整性失效记录。
9. Career Portfolio 只读取完整性通过、状态为 `complete` 且已经具名人工验收的结果。

## 状态应该怎样理解

| 状态 | 含义 | 用户动作 |
| --- | --- | --- |
| `draft` | 输入或任务刚建立 | 补齐身份和范围 |
| `needs_human` | 单位、身份、参数或范围不确定 | 人工核对后批准或拒绝 |
| `approved` | 当前对象和版本已获具名批准 | 才可进入受控执行 |
| `running` | 登记的确定性处理或外部工具正在运行 | 等待完成，不重复启动 |
| `passed` / `warning` | QC 通过或带局限保留 | 阅读问题清单，必要时接受警告 |
| `blocked` / `rejected` | 系统阻止或人工否决 | 解决条件后建立新修订，不绕过门禁 |
| `complete` | 结果、证据、复核和 Manifest 齐全 | 可进入成果验收判断 |
| `invalidated` | 输入、输出或 Manifest 被未登记修改 | 停止复用，返回来源模块调查 |

## 九个工作区入口

| 工作区 | 主要入口 | 当前用途 |
| --- | --- | --- |
| 数据接入 | 数据与物理 → 数据质量与扩展准备 | 字段、单位、试样身份、逐值 QC 和入库审批 |
| Physics Engine | 数据与物理 → Physics Engine | 版本化经验公式、适用范围、残差和模型卡 |
| 可追溯统计 | 数据与物理 → 可追溯统计 | 描述统计、组级 QC、报告复核 |
| EBSD 与 SEM | 组织与证据 | 文件登记、参数确认、外部运行和人工复核 |
| 研究助手 | 研究助手 → 智能助手 | 基于已验证证据的受限解释 |
| 模型实验室 | 模型与自动化 → 模型实验室 | 数据版本、模型版本、运行参数和结果复核 |
| 自动化任务 | 模型与自动化 → 任务与结果 | 只读查看现有任务状态；完整治理执行延期 |
| 科研会话 | 研究助手 → 科研会话 | 问题、证据、阶段结论、局限和下一步 |
| 作品集 | Career Portfolio | 只展示具名验收的完整成果 |

## 常见失败怎样处理

- 未知单位或关键字段缺失：返回数据接入补充证据，不要把缺失值当作 0。
- 样品或试样身份冲突：确认物理对象后建立新修订，不覆盖已有主键。
- 未批准执行：先完成具名审批，审批必须绑定当前对象摘要。
- 完整性失效：不要修改或覆盖原包；保留现场并重新生成新的仅追加结果。
- SteelData 或 SteelStats 不可用：根据页面提示检查同级项目和独立虚拟环境；Workbench 核心页面与离线测试仍可运行。
- 云端 AI 不可用：研究助手保持离线，数据处理、Physics、统计、质量门禁和 T40 合成演示不受影响。
