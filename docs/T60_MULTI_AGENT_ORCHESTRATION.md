# T60 材料科研多智能体框架

## 结论

SteelAI Workbench 已在阶段五治理内核上增加轻量多智能体编排。这里的“智能体”是职责、工具权限、输入输出和停止条件的组合，不是能够自由修改数据或自行批准结果的聊天角色。编排器可在普通个人电脑上运行，云端模型只是可选解释环节。

## 五类职责

| 角色 | 负责内容 | 允许工具 | 明确禁止 |
| --- | --- | --- | --- |
| 规划角色 | 拆解科研请求、登记停止条件 | 能力清单 | 审批、正式写入、Shell |
| 数据角色 | 汇总已核验且已授权的证据引用 | 读取核验证据 | 修改来源、绕过权限 |
| 统计与物理角色 | 运行确定性描述统计和 Physics Card | 描述统计、物理卡 | 猜测缺失值、替代实验真值 |
| 材料解释角色 | 生成证据绑定的受限解释和局限 | 受限材料解释 | 无来源结论、因果升级 |
| 审查角色 | 核对主张与证据、阻断越界输出 | 主张证据校验 | 代替人工接纳结果 |

所有角色均没有人工审批、正式写入、来源修改和任意命令权限。

## 人工关口

`plan_approval` 位于数据角色执行前，`result_acceptance` 位于流程完成前。两个关口都接受 approved、rejected、terminated 三种决定，并要求具名人工身份和理由。Agent、system、model 等身份不能成为审核人。

机器审查角色可以把无证据主张稳定阻断为 `GOV-EVIDENCE-001`，但不能把候选结果批准为科研结论。成功演示的人工决定是公开合成夹具，只证明工程流程，不代表真实实验审批。

## 可追溯交接与工具调用

每次交接保存任务 ID、交出角色、接收角色、责任角色、证据引用、输出状态和时间。工具调用只保存工具名、角色、参数摘要、尝试次数、状态、结果摘要、错误码和耗时，不保存原始参数或模型提示词。运行包使用阶段五 Governance Manifest、SHA-256、COMPLETE 标记和仅追加发布。

## 冻结演示

| 场景 | 预期结果 | 关键证明 |
| --- | --- | --- |
| success | complete | 五角色完成交接，机器审查通过，具名人工接纳 |
| insufficient_evidence | blocked | 无已核验证据时，数据角色关闭式阻断 |
| tool_failure | blocked | 描述统计工具失败后只重试一次，再以稳定错误码阻断 |
| offline_success | complete | 云端不可用时，确定性数据、统计和物理结果仍完成，解释降级 |

入口为“研究助手 → 多智能体协作”，也可运行 `python -m steelai.multi_agent_orchestrator <scenario>`。演示不会读取真实科研资料。

## 验收边界

- 审查角色能阻止无来源主张进入候选报告。
- 人工能批准、拒绝或结束关键节点。
- 云模型不可用不影响确定性处理和既有报告。
- 所有输出保持 `working_candidate` 或 `synthetic_demo_only`；真实成果仍需后续明确的科研验收与披露审查。
