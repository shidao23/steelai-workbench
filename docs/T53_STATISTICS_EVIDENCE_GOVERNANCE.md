# T53 可追溯统计与证据验证治理适配

状态：`Done`
依赖：T51 共享科研治理包与 T52 数据治理适配
实施日期：2026-09-09

## 1. 目标

T53 让通过 SteelStats 独立复核的描述统计报告成为可验证科研产物，并把可以怎样表述、必须怎样谨慎表述和禁止怎样表述绑定到报告身份、治理状态、证据等级和质量状态。T53 不改变 SteelStats 算法，不增加显著性检验或因果判断。

## 2. 统计治理链路

“数据与物理 → 可追溯统计”现在执行以下链路：

1. 校验 SteelData 结果包和源 Manifest。
2. 逐一登记物理试样到研究样品的对应关系。
3. 登记实验方法版本、具名审核人、审核说明和逐值纳入决定。
4. 通过独立 CLI 运行 SteelStats 描述统计并调用其 `verify-report` 复核。
5. 依据来源、输入包和结果包文件摘要生成稳定统计报告身份。
6. 经公共状态机、审批、QC 和正式写入门禁后，仅追加发布 Governance Manifest。

SteelStats 仍由同级独立项目和独立 Python 环境负责统计。Workbench 只使用公开 CLI 与结果文件，不导入 SteelStats 内部代码。

## 3. 治理包内容

正式包位于 `outputs/governed_statistics/<governance_id>/`，包含：

- `traceable_statistics_report.md`：治理信息、表述边界和 SteelStats 原报告；
- `statistics_registry.json`：统计单位、分组、方法版本、组样本量和来源登记；
- `traceability_index.json`：报告到统计单位、观测、纳入决定和源摘要的反查入口；
- `evidence_statement_rules.json`：证据等级及允许、谨慎、禁止表述；
- `governance_record.json`：审批和完整状态轨迹；
- `input/`：冻结的分析计划、统计单位、观测和纳入决定；
- `steelstats/`：独立 SteelStats 的报告、结果、Manifest 和完成标记；
- `governance_manifest.json` 与 `COMPLETE`：全部文件摘要和完整性绑定。

相同来源、输入和结果可幂等复用同一完整包。既有包内容不同、文件缺失或被修改时，系统返回 `GOV-INTEGRITY-001` 或 `GOV-DUPLICATE-001`，不覆盖原包。

## 4. 证据表述规则

证据等级依据完整治理状态、证据类别、组级 QC、统计单位和最低组样本量生成。等级只控制描述性表述强度，不代表已经完成推断统计或因果识别。

允许表述包括登记组的 n、均值、中位数、样本标准差、最小值、最大值和极差，以及明确标注为描述性的组间方向。谨慎表述必须同时报告统计单位、组样本量、方法版本、纳入决定、排除记录和 QC 局限。

以下表述保持禁止：

- 把描述性差异写成统计显著差异或总体无差异；
- 从均值方向推断成分、工艺或组织的因果作用；
- 省略统计单位、样本量、排除记录或来源状态；
- 把统计输出写回并覆盖 SteelData 或正式实验观测。

合成演示包的证据等级为 `NA`，只能说明流程能力。warning 报告必须有与当前摘要绑定的 `warning_accepted` 人工记录，才能完成治理发布。

## 5. 证据验证接入

“研究助手 → 证据验证”自动检查最新治理统计包。只有 Governance Manifest 完整性为 `passed` 的包才会进入机械性能证据登记，并显示治理状态、统计 QC、证据等级和表述规则。最新包被篡改时页面明确显示 `invalidated`，不再把它纳入证据或报告。

原有 B/R 结论矩阵继续保留。T53 只用治理统计包增强来源与表述约束，不自动改变既有实验事实、研究假设或因果就绪度。

## 6. 验收与边界

专项测试覆盖报告反查、统计单位和逐值决定一致性、证据表述边界、warning 接受、未复核拒绝、幂等复用和篡改失效。跨项目测试实际调用独立 SteelStats CLI，并在运行前后逐文件比较 SteelData 源包 SHA-256，确认没有回写。

T53 不修改真实科研数据，不迁移历史报告，不做显著性检验、异常值自动删除、缺失值填补或因果推断，也不改变 T40 冻结旗舰演示。其他图像、Agent 和统一成果视图由后续任务继续接入公共治理内核。
