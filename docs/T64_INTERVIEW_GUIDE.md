# T64 面试讲解清单

## 一句话定位

我做的是一个面向材料科研的可追溯 AI 工作台：确定性代码负责数据、统计、物理和完整性，云端模型只在证据边界内组织解释，人工保留批准权。

## 五分钟讲解结构

1. **问题**：科研数据来自多个工具，最危险的不是不会调用模型，而是单位、样品关系、证据来源和结论边界失控。
2. **架构**：数据契约与 QC → 人工决策 → Statistics、Physics 或模型任务 → 证据网关 → 报告与作品集过滤。
3. **真实案例**：UCI Steel Plates Faults，1941 条记录、27 个特征、7 类缺陷；固定 60/20/20 划分，CPU kNN，报告 accuracy、balanced accuracy 和 macro F1，同时写清数据缺少成分、工艺和组织信息。
4. **Agent 设计**：五个角色使用固定工具；计划和结果都有人工关口；失败重试一次后关闭式阻断；不能审批、正式写入或运行任意命令。
5. **可信评估**：T63 用相同任务分别测纯人工、单智能体和多智能体，提前冻结指标；没有数据就不宣称优势。

## 高频追问

**为什么不用本地大模型？** 项目把模型作为可替换的解释层；本机只运行确定性处理和 Streamlit，云模型按需调用，降低个人电脑负担和数据泄露压力。

**如何控制幻觉？** Agent 只能读取已登记的结构化证据，回答固定分为事实、判断、假设、证据与局限、下一步；正式写入和科学批准仍需人工。

**T62 能否指导炼钢工艺？** 不能。它是公开钢板表面缺陷分类案例，没有成分、工艺、组织和可靠批次键，因此不能推出冶金机制、生产部署或工艺推荐。

**多智能体是否一定更好？** 不预设。T63 要求同题、同输入、双重复并记录完成率、关键错误、修订、耗时、Token、费用和追溯完整率；不支持优势时如实保留无优势结果。

**自己写代码的价值是什么？** 可以把研究规则、权限和失败边界写成可测试契约；第三方工具只负责局部能力，核心身份、审批、审计和发布边界仍由项目掌握。
