# T70 外部文件标准化入库

## 目标

把 SteelAI 的首要日常用途收敛为一条真实数据入口：用户选择外部 CSV、TSV 或 XLSX，核对字段和单位后，将标准记录追加到现有 `data/processed/*.csv` 数据层。系统不修改原文件，不用空白代替 0，不猜未知单位，也不覆盖已有主键。

## 使用流程

1. 打开“数据与物理 → 数据接入与质控 → 外部文件标准化入库”。
2. 选择一个不超过 20 MiB 的 CSV、TSV 或 XLSX；XLSX 需明确选择工作表。
3. 选择目标数据层。新样品先进入 `samples.csv`，其他记录只能引用已登记 `sample_id`。
4. 核对来源列到 SteelAI 标准字段的映射；必要时填写本批固定值。
5. 对每个有物理量含义的宽表数值明确来源单位。系统只执行登记过的确定性换算，例如 GPa → MPa、mass ppm → wt.%、K → ℃。
6. 查看标准化记录、错误、警告和换算表。错误未解决时按钮保持禁用。
7. 填写审核人和说明，确认后仅追加写入。成功结果产生治理审计编号与可验证 Manifest。

## 数据层

当前“标准化数据库”是 Git 忽略边界保护下的结构化 CSV 数据层，而不是网络数据库：

- 主数据和摘要：`samples.csv`、`composition.csv`、`process.csv`、`microstructure.csv`、`properties.csv`；
- 可追溯长表：`composition_observations.csv`、`process_steps.csv`、`microstructure_observations.csv`、`property_observations.csv`、`physics_observations.csv`。

长表优先保存逐炉次、逐步骤、逐试样、逐视场和逐观测记录。摘要表只适合已经明确汇总口径的一行一条件数据。

## 安全与科学边界

- 原文件仅以内存上传字节读取；不会被改写，也不会发送给云端 Agent。
- 审计包保存来源 SHA-256、字段映射、固定值和单位换算，不把原始实验文件加入公开仓库。
- 物理试样、炉次、批次和视场身份必须来自真实记录；系统只允许为普通观测记录生成稳定 `observation_id`，不会生成物理试样编号。
- 未知单位、缺少必要字段、未登记样品、重复主键、非有限数值和不支持的换算均关闭式阻断。
- XLSX 公式单元格读取缓存显示值并产生显式警告；正式提交前必须回到原表核对。
- 本任务解决平面数据表的标准化。`ZHT.A*` 热模拟曲线已由 T71 增加专用只读解析与预录入；其他复杂仪器报告、多区块报告和未登记格式继续由高级 SteelData 流程处理。

## 验收

- CSV/TSV/XLSX 可在不增加 Workbench 运行依赖的情况下读取。
- 中英文常见字段可产生确定性映射建议，最终映射由人确认。
- GPa → MPa 等登记换算有测试；来源单位未确认时不能提交。
- 新样品可通过 `samples.csv` 受控登记，其他表不能绕过样品注册。
- 标准化结果复用 T52 人工审批、写入锁、提交前重检、主键冲突检查、仅追加发布和治理 Manifest。
