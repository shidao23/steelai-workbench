# T22：SteelData 映射建议人工审批

状态：Done。入口位于“数据与物理 → 数据质量与扩展准备 → SteelData 标准化接入”的“映射建议人工审批（T22）”区域，不新增侧栏页面。

## 审批体验

页面只在用户点击刷新和加载后读取建议，并一次只允许选择一条。审批前展示：

- 相对来源文件名、源文件原摘要和当前摘要是否一致；
- 建议状态、修订、领域、理由、字段映射、来源/目标单位、证据和置信度；
- 结构化不确定性与风险；
- 与最近批准配置的逐项差异；
- 建议内容摘要和建议 profile 摘要。

批准与驳回都要求用户自己填写审批人和说明，并勾选与决定对应的确认项。页面不预填审核人，不提供批量批准，也不向 DSH/Agent 暴露审批能力。

## 摘要与状态边界

批准文件同时绑定 suggestion ID、建议内容 SHA-256、审批时修订和 profile SHA-256。人工决定记录另存建议摘要、批准记录摘要；界面另外显示决定记录摘要。因此修改配置会产生不同的建议摘要，旧批准不能验证新配置。

提交时 SteelData 重新读取记录并核对预期修订和摘要，以单建议锁串行化决定。第一次决定后状态离开 `candidate/needs_human`；重复点击或旧页面提交会因修订/状态冲突失败。驳回只生成决定记录，不生成批准文件。

## T22 不做什么

T22 不运行获准建议、不写 Workbench `data/processed/`、不自动重试，也不把审批权交给 Agent。批准后的锁定执行、幂等运行、失败恢复和重新运行属于 T23。
