# 已知限制

- 当前毕业主线正式覆盖拉伸性能的屈服强度、抗拉强度和伸长率，并已为登记的 `ZHT.A*` 热模拟运行/点表开放治理写入。成分、其他仪器曲线、冲击、硬度、SEM、EBSD 和 XRD 尚未形成同等级端到端数据契约。
- 热模拟运行表和曲线点表采用同锁预构建与失败回退，但底层仍是本地 CSV，不具备网络数据库的多用户事务与权限隔离；提交时不要用 Excel 等程序占用或直接改写目标文件。
- 公开旗舰演示使用合成数据和冻结的人工作决定夹具，不代表真实实验审核，也不能替代研究者复核。
- SteelStats 当前只做描述统计和组级 QC，不做显著性检验、因果判断或工艺推荐。
- Physics Engine 输出是带适用范围说明的经验估算，不是实验真值；缺失输入不会补零。
- Research Agent 可选调用云模型，但只允许读取经审计的结构化摘要。模型回答可能出错，不能直接写入数据、批准映射或启动执行。
- 公开候选仓库不包含真实原始文件、处理后科研数据、运行结果、个人审批记录、模型权重或本机路径。
- 完整 T40 跨模块重放依赖独立的 SteelData 与 SteelStats 项目；只克隆本仓库时可以运行界面、质量门禁和离线测试，但不能凭空重建这两个外部模块。
- 当前主要由单人完成本地 Windows 验收；GitHub Actions 提供 Linux/Windows 自动检查，但仍需要公开发布后的社区环境反馈。
- 自动化任务尚未完整迁移到共享治理内核。v0.2 只提供现有 AutoDimple 状态记录和统一中心展示，不能把自动化输出直接升级为已验收成果。
- `v0.2.0-rc1` 是本地冻结候选；Git 提交、标签和 GitHub Release 需要项目负责人另行批准。
- T62 是钢板表面缺陷分类而非成分—性能预测。UCI 来源没有板号/批次分组键，也缺少成分、工艺和组织信息；无法完全排除隐藏采集组泄漏，不能据此宣称生产部署、冶金机制或工艺推荐。
- T63 当前只完成评测契约、测量工具和结构校准，尚未完成纯人工、单智能体、多智能体共 24 条真实同题测量；因此没有效率优势结论。未来结论也只适用于冻结任务、模型版本和运行环境。
- T64 当前是岗位作品集发布准备包，不是最终 GitHub Release。三分钟视频、技术报告或软件型论文初稿、全新环境独立复现、简历定稿和最终人工公开审查尚未完成。
- Enterprise Lab（T80–T84，可选参考实现，阶段已冻结）的限制摘要：只在 PostgreSQL 18.6 **单实例**验证，未覆盖复制、PgBouncer 或托管服务；没有生产备份、高可用、监控与告警；没有常驻 dispatcher/worker（只有有限调用）、没有调度器与死信队列；投递与执行都是 **at-least-once**，下游必须以 `event_id`、Handler 外部副作用必须以稳定 `job_id` 幂等；未接入默认应用（`app.py`、`pages/`、Streamlit 默认入口与 T76 启动器都不导入它）；**不得据此宣称生产就绪**，也不代表 Kafka、微服务或 API 已完成。详见 `docs/enterprise/T85_ENTERPRISE_LAB_PHASE_CLOSEOUT.md`。
- **T86 CALPHAD（可选、可关闭，当前 `Blocked`）**：`pycalphad==0.11.2` 已装入独立环境 `.venv-pycalphad`（34 个包全部哈希锁定），TU Wien 原件 MatCalc `mc_fe v2.062` 无法被 pycalphad 0.11.2 解析（平台编码打开失败；显式编码后在**第 180 行 `REFERENCE_ELEMENT`** 处抛 `ParseException`，`ADD_COMPOSITION_SET`、`ATTACH_CONTRIBUTION`、`CREATE_NEW_PHASE`、`HMVA` 逐一验证同样不支持），原件只保留用于溯源与差异审计。第三阶段按负责人决定改用**第三方社区派生候选** `mc_fe_v2062_clean`（提交 `19b1164…`，SHA-256 `7cf37dd4…`）；该文件**未被修改**，差异审计为"仅语法修复、0 条未解释差异"，上游 15 项二元检查 **15/15** 复现、项目相关检查 **18/18** 通过。
- **T86 阻断级环境限制（第三阶段实测）**：本机 `pycalphad==0.11.2` 对**组元列表长度 ≥14** 的体系无法求解（实测上界 13 = Fe + 11 个合金元素 + VA）。失败形态包括 `MemoryError`（无法分配 10.9 GiB，形状 `(1, 1, 54, 933583, 29)`）、`pycalphad/core/minimizer` 原生扩展内的 `0xC0000005` / `0xC0000374` 中止，以及无结果的内存无界增长。该边界在 pycalphad **自带**数据库 `COST507` 上完全复现（同为 13 可解 / 14 失败），且与相列表、`pdens`、具体元素、线程栈均无关。B-DQ 与 R-DQ 都需要 16 个组元条目，因此**当前环境无法产出任何真实炉次的相分数曲线**。适配器为关闭式失败（`CALPHAD-RUN-001` + worker `CALPHAD-WORKER-MEMORY-001`），**不会**为迁就求解器而静默丢弃组元或裁剪相列表。
- **T86 已知模型损失（永久写入每个结果）**：社区派生库中 `ATTACH_CONTRIBUTION`（BCC_B2 有序-无序耦合）、`ADD_COMPOSITION_SET`（MC/MX 碳氮化物组合集）、21 条 `HMVA` 参数与 `REFERENCE_ELEMENT` 均被注释。BCC_B2 是否会进入 B-DQ/R-DQ 稳定组合、这些损失对目标窗口的影响有多大，**均未证明**，因此一律记为 `unknown_model_impact`，**不声明"无影响"**。
- T86 结果一旦产生也必须按**缩减成分体系**解释：R-DQ 的 As、Sn、Sb 未被任何可用开源数据库建模，两炉的 O、W 只有字段声明没有测量值；限制声明已嵌入页面、Markdown、JSON 与 CSV 的**每个**导出文件。排除决定是版本化、逐条枚举并与数据库身份绑定的（`config/calphad_exclusion_policy_v1.1.json`，无通配符、无通用忽略开关），不能据此判断这些元素对偏聚、夹杂、晶界脆化、相稳定性或性能的影响。
- T86 的 mc_fe 系数据库**不随仓库分发**（上游 ODbL 1.0 + DbCL 1.0，与 pycalphad 的 MIT 相互独立；社区派生库同为 ODbL 派生数据库）；公开仓库只有登记模板、获取说明、差异审计结论与门禁证据。数据库自身的适用温区只写在文件注释（673–2000 K），文件**没有** `TEMPERATURE_LIMITS` 命令。**第三方社区派生候选不得被描述为 TU Wien 官方 pycalphad 兼容版、pycalphad 官方数据库或 SteelAI 已验证数据库。**
- T86 尚未做：洁净环境按锁重装验证（`.venv-pycalphad` 由本机缓存的 CPython 创建，**不是自包含环境**）、真实炉次的单温度与多温度试算、真实炉次的相分数合计/收敛核对、真实炉次的重复运行一致性。详见 `docs/T86_PHASE3_COMMUNITY_COMPATIBILITY.md` 与 `docs/T86_PHASE2_ENVIRONMENT_AND_GATES.md`。
- **T86 第四阶段（固定缩减体系与固定相范围，仍 `Blocked`）**：已建立固定、版本化的 `steel_matrix_equilibrium_v1`（12 组元）与 `steel_matrix_major_carbides_v1`（7 相），**没有**任何通用元素/相选择开关；真实运行前必须具名批准（`reviewer_id`／批准时间／批准理由＋确认文本），代码不代填姓名，缺失即 `CALPHAD-COMP-011` 阻断。
- **T86 阻断项（第四阶段实测）**：十步验证中第 1–5、7、9 步通过（含 R-DQ 全部 54 点收敛、合计 0.9999999998–1.0000000004、重复运行最大绝对差 3×10⁻⁹），但**第 6 步 B-DQ 在 875 °C 的多温度批量求解不收敛**（已实现有界单点重算，重算后仍未收敛）。同一请求在不同进程中分别出现 0/1/2/3 个未收敛点，`pdens` 500–8000 均无法消除；单温度独立调用可收敛，说明失败来自批量求解热启动路径。因此**不得**标记为 `pilot_ready_pending_scientific_review`。
- **T86 第四阶段发现的缺陷（已修复）**：组元列表缺少空位 `VA` 时，pycalphad **不报错**，而是返回物理错误的结果（B-DQ 在 400 °C 报 LIQUID 0.97），且相分数合计仍为 0.99942 —— **只检查合计无法发现**。worker 现已在数据库声明 `VA` 时总是加入，并输出 `pycalphad_components`；验证脚本新增物理合理性检查（1000 °C 以下不得出现液相、1500 °C 以上必须出现液相、700 °C 以下必须有基体相）。
- T86 第四阶段结果一律命名为 `12-component reduced-system matrix equilibrium prediction`，不得称为完整钢种热力学计算／完整相图／全成分平衡／实际组织预测／析出动力学结果。本阶段明确不计算 BCC_B2、MC/MX 组合碳氮化物、氮化物、硼化物、硫化物、磷化物、氧化物与夹杂物、As/Sn/Sb 相关相，以及析出动力学、偏聚、晶界脆化与实际组织含量。详见 `docs/T86_PHASE4_REDUCED_SYSTEM.md`。
- **T86 第五阶段（正式路径改为独立单点进程，仍 `Blocked`）**：正式 `solver_mode=independent_single_point_process_v1` —— 每个温度点一个全新 worker 进程、每进程只解一个温度、**严格串行**、无热启动，输入除温度外逐点相同；旧的批量热启动路径降级为 `diagnostic_only`。缺少任何点时**不输出部分正式曲线**；诊断重试（上限 1 次）不会把失败点改成通过，也不会拼进正式曲线。
- **T86 阻断项（第五阶段实测）**：324 个独立点（B-DQ 3 轮 + R-DQ 3 轮 × 54 点）验收中，**320 个首次调用即成功（0.9877），4 个失败点全部是 B-DQ 的 875 °C 与 900 °C**，且诊断重试也失败；无 native abort、`MemoryError` 或超时。决定性证据：在**全新进程**中重复求解同一单点条件，B-DQ 900 °C 成功 1/8 次、875 °C 成功 2/4 次，失败形态是"没有任何相摩尔数"。这说明第四阶段把失败归因于批量热启动是**不完整**的：该体系在本机 pycalphad 0.11.2 下于 α/γ 相界附近本身求解不确定。因此 T86 保持 `Blocked`，**不得**标记 `pilot_ready_pending_scientific_review`。R-DQ 三轮全部 54/54 且三轮最大重复差 1.3×10⁻⁹（容差 1×10⁻⁷）。
- **T86 第二阻断项（模式差异）**：R-DQ 旧批量模式与新独立点模式在 54 个共同收敛点中有 **1 个点（675 °C）相差 1.069×10⁻⁴**，远超 1×10⁻⁷：两种模式找到相同的 BCC_A2+CEMENTITE+FCC_A1 三相组合，但相分数不同。按"不得自行选择其中一条曲线"的规则，两条曲线都不发布，差异如实报告。
- T86 第五阶段**未**删除 875/900 °C、未改步长、未插值或平滑、未按结果调整 `pdens`、未挑选成功的那一次；这些规避手段已被政策 `forbidden` 列表逐条禁止。详见 `docs/T86_PHASE5_INDEPENDENT_POINTS.md`。
