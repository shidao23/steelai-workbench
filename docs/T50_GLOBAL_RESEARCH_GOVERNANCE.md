# T50 全局科研治理规范 v1.0

状态：`frozen`
生效日期：2026-09-09
机器契约：`config/global_research_governance_v1.0.json`

## 1. T50 的定位

T50 只冻结规则，不迁移真实数据、不重构全部页面、不改变 T40 旗舰演示。它为 T51 及以后建立统一语言：同一种状态在不同工作区必须表达同一种风险，同一个结果必须能说明“它是谁、从哪里来、由什么方法产生、谁批准、是否完整”。

统一原则：空白是未知值，不是 0；正式写入仅追加；失败关闭；被验收的产物不得静默覆盖；AI 只能建议、解释和总结，不能批准、代替实验真值或自行写入正式证据。

## 2. 四类内容必须分开

| 类别 | 含义 | 可否当实验真值 | 正式使用条件 |
| --- | --- | --- | --- |
| 真实科研数据 | 来自已识别的真实实验或表征来源 | 可以，但不是自动可以 | 身份、来源、审批、QC、溯源和完整性全部满足 |
| 公开合成数据 | 为演示、测试和界面排练而编造 | 不可以 | 始终标记 `synthetic_only`，与正式数据区隔离 |
| 模型输出 | 公式估算、预测、分割或生成结果 | 不可以 | 可作为“模型结果”接受，但必须保留版本、输入、局限和人工复核 |
| 人工结论 | 研究人员基于证据作出的判断或解释 | 不是观测值 | 必须记录作者、证据、范围、局限和时间 |

因此，“模型算出来了”“AI 说了”“演示跑通了”都不能直接写成“实验已经证明”。

## 3. 研究对象身份

每个对象使用“对象类型 + 稳定 ID + 修订号 + 内容摘要”识别。材料、炉次、样品、物理试样、来源、观测、图像视场、任务、运行、结果、证据、审批、科研会话和作品集条目各自有独立身份。

显示名称、表格行号、文件名和自然语言描述都不能单独充当身份。一个物理试样不能因为出现在三行结果中就变成三个试样；一张图像视场、一个 EBSD 像素或一个统计均值也不能冒充物理试样。

## 4. 全局状态机

| 状态 | 统一含义 | 谁可推动关键转换 |
| --- | --- | --- |
| `draft` | 已创建，但没有执行许可 | 系统可发现问题；人可送审、批准或驳回 |
| `needs_human` | 身份、单位、范围、参数、证据或接纳不确定 | 只能由可追溯的人工决定解除 |
| `approved` | 人工已批准当前摘要绑定的修订和范围 | 系统核验摘要后才可执行 |
| `running` | 获批的确定性代码或登记工具正在执行 | 系统记录运行身份和状态 |
| `passed` | 声明的技术 QC 已通过 | 仍可能等待最终人工接纳 |
| `warning` | 可保留，但必须明确局限 | 正式使用前必须人工接受警告和范围 |
| `rejected` | 人工明确驳回当前修订 | 不执行、不正式写入 |
| `blocked` | 必要条件失败或缺失 | 不产生正式结果；修复后重新进入受控流程 |
| `complete` | 结果、溯源、完整性和必要复核全部完成 | 可按结果等级进入后续工作区 |
| `invalidated` | 已治理对象或绑定输入被未登记地改变 | 原批准不再有效，必须登记新修订并复核 |

禁止的捷径包括：`draft → running`、`needs_human → running`、`blocked → complete`。唯一正常执行入口是 `approved → running`。完成产物发生变化时必须进入 `invalidated`，不能保持“已完成”。

## 5. `needs_human` 与 `blocked` 触发规则

`needs_human` 表示“科学或责任判断必须由人作出”，包括：

- 对象身份或父子对应不明确；
- 物理量单位未知、冲突或不兼容；
- 公式、模型、方法或结论的适用范围不明确；
- 表征、分割、建模或自动化参数需要科学选择；
- 证据冲突、不完整或无法支持唯一解释；
- 带警告结果拟进入正式用途；
- AI 文本拟转为研究结论；
- 作品集内容的验收或公开范围不明确。

`blocked` 表示“系统必须停止且不得产生正式结果”，包括：

- 缺少有效审批或状态跳转非法；
- 内容摘要、manifest 或完成标记缺失/不一致；
- schema、字段、单位或关系校验失败；
- 仅追加主键与既有不同内容冲突；
- 来源缺失、未登记、不支持或审批后改变；
- 隐私、许可证或公开边界不满足；
- Agent 尝试审批、正式写入或任意工具执行；
- 运行环境、公式或模型版本无法复现；
- 合成数据或未复核模型输出被请求写为正式结果；
- 写入目标越界或试图修改来源/已验收包。

每个触发条件在机器契约中都有唯一错误码、目标状态和恢复办法。`needs_human` 不是报错，`blocked` 也不能靠“继续运行”消失。

## 6. 结果等级

| 结果等级 | 最低状态 | 可否正式引用 | 说明 |
| --- | --- | --- | --- |
| `working_candidate` | `draft` | 否 | 未验收中间结果 |
| `synthetic_demo_only` | `passed` | 否 | 只能证明演示流程行为 |
| `model_result` | `complete` | 可以，须标明非测量 | 已复核的公式或模型结果 |
| `verified_output` | `passed` | 可以，须说明尚未科学接纳时的边界 | 技术完整性已验证 |
| `accepted_evidence` | `complete` | 可以 | 在声明范围内已验收的证据 |
| `human_conclusion` | `complete` | 可以 | 人工撰写且链接证据与局限的结论 |

## 7. 人工审批记录

人工审批必须包含审批 ID、对象类型和 ID、对象修订、对象摘要、决定、审核人、决定时间、适用范围、理由以及本治理契约 ID。批准、驳回和警告接受记录均为仅追加记录。

审批只对绑定的内容摘要和修订有效。源文件、配置、参数或结果发生变化，旧审批随即失效。AI/Agent 不能成为审核人；未来若允许批量审批，必须另行冻结同质范围和抽样证据，v1.0 不允许默认批量批准。

## 8. 正式写入的十个门槛

正式数据区、证据索引或作品集发布前必须同时满足：稳定身份、来源登记、schema/单位/关系通过、必要人工审批有效、QC 通过或警告获明确接受、全链路溯源完整、manifest 和摘要通过、内容类别明确、目标在白名单且仅追加、状态转换合法。

任何一项失败都不得“先写进去再补手续”。新产物写入批准的输出区；来源文件和已验收结果包保持只读。

## 9. 九个工作区覆盖矩阵

| 工作区 | 冻结目标链路 | 主要人工门槛 | 合法正式结果 |
| --- | --- | --- | --- |
| 数据接入 | 字段识别 → 人工审批 → 标准化 → 逐值 QC → 入库 | 审批来源绑定映射；另行确认物理试样对应 | `verified_output`、`accepted_evidence` |
| Physics Engine | 输入完整性 → 公式版本 → 适用范围 → 计算 → 残差 → 模型卡 | 确认适用范围并接受警告 | `model_result` |
| 可追溯统计 | 统计身份 → 纳入决定 → 描述统计 → 组级 QC → 报告复核 | 确认试样纳入和方法版本；复核报告 | `verified_output`、`accepted_evidence` |
| EBSD/SEM | 原始文件登记 → 参数确认 → 模型运行 → 人工复核 → 结果索引 | 运行前确认参数；索引前复核结果 | `model_result`、`accepted_evidence` |
| 研究助手 | 只读已验证证据 → 事实/判断/假设标注 → 受限解释 | 人对研究结论负责 | `human_conclusion` |
| 模型实验室 | 数据版本 → 模型版本 → 运行参数 → 结果 → 人工验收 | 批准运行配置；验收模型卡 | `model_result` |
| 自动化任务 | 提议任务 → 批准执行 → 状态记录 → 产物验证 | 批准精确白名单任务 | `verified_output` |
| 科研会话 | 研究问题 → 证据引用 → 阶段结论 → 局限 → 下一步 | 研究者接受阶段结论和局限 | `human_conclusion` |
| 作品集 | 只取已验收成果 → 证据投影 → 公开复核 → 发布 | 确认成果验收、脱敏和公开范围 | `accepted_evidence`、`human_conclusion`；合成演示仍必须标注 |

## 11. 与现有系统的关系

当前各页面仍保留自己的旧状态词，例如 `candidate`、`completed`、`failed` 和 `not_committed`。T50 只登记这些现状并冻结目标语义，不在本任务强行迁移。T51 应实现共享治理包和显式映射器；后续每次只迁移一个工作区，并以本契约为验收基准。

T40 的成功链、未知单位失败链、公开合成标记和完整性身份保持原样。T50 不读取、不复制、不改写任何真实实验数据。

## 12. T50 验收结论

- 九个工作区均已映射到统一状态、结果等级、身份和人工门槛；
- 每个 `needs_human` 和 `blocked` 类别都有显式触发、代码和解决/恢复路径；
- 真实数据、合成数据、模型输出和人工结论在语义及准入上严格分离；
- 机器契约由自动测试校验；
- T50 仅新增规范、契约和测试，T40 与真实数据不发生变化。
